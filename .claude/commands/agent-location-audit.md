## Context
You are helping the user understand which AI agent instances are running and where (local Mac, Linux PC, VPS). This prevents confusion when multiple agents appear to be active simultaneously.

## Your Task

Audit all running AI agent processes across available machines to identify their locations and determine which is the "active" agent.

### Steps

1. **Check Local Machine (Current)**
   ```bash
   echo "=== LOCAL MACHINE: $(hostname) ==="
   ps aux | grep -E 'openclaw|claude|nexus' | grep -v grep
   ```

2. **Check VPS (if SSH access available)**
   ```bash
   echo "=== VPS: srv1308064.hstgr.cloud ==="
   ssh -i ~/.ssh/id_ed25519 root@srv1308064.hstgr.cloud "ps aux | grep -E 'openclaw|claude|nexus' | grep -v grep" 2>/dev/null || echo "VPS not accessible via SSH"
   ```

3. **Check Linux PC (if accessible via Tailscale/SSH)**
   Ask user for Linux PC hostname/IP if not known:
   ```bash
   echo "=== LINUX PC ==="
   ssh USER@LINUX_PC_HOST "ps aux | grep -E 'openclaw|claude|nexus' | grep -v grep" 2>/dev/null || echo "Linux PC not accessible"
   ```

4. **Check Active Network Connections**
   ```bash
   echo "=== ACTIVE OPENCLAW CONNECTIONS ==="
   netstat -an | grep 18789 2>/dev/null || lsof -i :18789 2>/dev/null || echo "No OpenClaw gateway connections detected"
   ```

5. **Identify SSH Tunnels/Connections**
   ```bash
   echo "=== ACTIVE SSH CONNECTIONS ==="
   ps aux | grep 'ssh' | grep -v grep
   ```

6. **Summarize Findings**
   Create a clear summary showing:
   - Which machines have agent processes running
   - Which processes are local vs remote
   - Which agent is connected via SSH tunnels
   - Recommendations for cleanup if multiple instances detected

### Decision Matrix

After audit, help user decide:

**If multiple agents detected:**
- Ask which location should be the "primary" agent
- Offer to kill processes on other machines
- Verify the remaining agent is the correct one

**If agent appears to be running via SSH:**
- Explain that closing SSH will disconnect the agent
- Offer to migrate agent to run natively on target machine
- Suggest using systemd/daemon mode instead of SSH session

**If no agent processes found:**
- Check if services are stopped: `systemctl --user status openclaw-gateway`
- Offer to start agent with proper configuration

### Guardrails
- **Never kill processes** without user confirmation
- VPS processes should be checked as root: `ssh root@srv1308064.hstgr.cloud`
- If user has moltbot, nexus, or other users on VPS, check all: `ssh USER@srv1308064.hstgr.cloud`
- Explain SSH vs daemon modes clearly - users often confuse them

### Common Scenarios

**Scenario 1: Agent running locally but user thinks it's on VPS**
- Check if there's an SSH tunnel to VPS
- Verify VPS processes: should see daemon process, not SSH session

**Scenario 2: Multiple instances responding**
- One is likely a zombie/orphaned process
- Check timestamps, kill older processes
- Restart primary instance to ensure clean state

**Scenario 3: Agent location confusion**
- Check OpenClaw config: `openclaw config show`
- Look at `workspace:` path - shows which machine's config is active
- Look at `gateway.remote.url` - shows which machine hosts gateway
