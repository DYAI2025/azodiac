## Context
You are configuring the OpenClaw AI agent. Based on learned user preferences, the default configuration should use minimax/MiniMax-M2.1 as the model and Tailscale for remote gateway access.

## Your Task

Configure or fix OpenClaw agent configuration, ensuring correct model, gateway, and workspace settings.

### Steps

1. **Check Current Configuration**
   ```bash
   openclaw config show
   ```
   Note any problematic settings (wrong model, gateway issues, etc.)

2. **Clean Corrupted Config (if needed)**
   If configuration appears broken or conflicts exist:
   ```bash
   # Backup old config
   cp ~/.openclaw/openclaw.json ~/.openclaw/openclaw.json.bak 2>/dev/null || true

   # Remove corrupted config
   rm -f ~/.openclaw/openclaw.json
   ```

3. **Set Model to MiniMax-M2.1**
   ```bash
   openclaw config set model minimax/MiniMax-M2.1
   openclaw config set provider openai
   ```

4. **Configure Gateway**
   Ask user which gateway mode they want:
   - **Local**: Gateway runs on this machine only
   - **Tailscale**: Gateway accessible via Tailscale network
   - **Remote**: Gateway runs on specific remote machine

   For Tailscale (recommended for multi-machine setups):
   ```bash
   openclaw config set gateway.mode remote
   openclaw config set gateway.remote.url ws://HOSTNAME.tail-scale.ts.net:18789
   ```

5. **Verify Configuration**
   ```bash
   openclaw config show
   ```

   Expected output should include:
   - model: minimax/MiniMax-M2.1
   - provider: openai
   - gateway configuration matching user's choice

6. **Test Agent Functionality**
   ```bash
   openclaw status
   ```

   If agent is not running, check:
   ```bash
   # Check if gateway is running
   ps aux | grep openclaw

   # Check logs for errors
   openclaw logs --follow
   ```

### Guardrails
- **Always use minimax/MiniMax-M2.1** as default model (NOT qwen-portal or other models)
- **Gateway should use Tailscale** for remote access unless user explicitly requests different setup
- If config shows "gateway.remote.url: ws://DYAI-maschine.local:18789", this is likely incorrect - clean and reconfigure
- If gateway is running as systemd service, restart after config changes: `systemctl --user restart openclaw-gateway`

### Common Issues

**"Unknown model" errors:**
- Config file has wrong model name
- Solution: Clean config and set to minimax/MiniMax-M2.1

**Gateway connection issues:**
- Check if gateway process is running: `ps aux | grep openclaw`
- Check firewall rules for port 18789
- Verify Tailscale is connected: `tailscale status`

**Config file conflicts:**
- Multiple config sources (local vs workspace)
- Solution: Use `rm -f ~/.openclaw/openclaw.json` and reconfigure from scratch

### Systemd Service Setup (Optional)

If user wants gateway to auto-start:
```bash
# Create systemd service
cat > ~/.config/systemd/user/openclaw-gateway.service <<EOF
[Unit]
Description=OpenClaw Gateway
After=network.target

[Service]
Type=simple
ExecStart=/usr/bin/openclaw gateway
Restart=always
Environment=PORT=18789

[Install]
WantedBy=default.target
EOF

# Enable and start
systemctl --user enable openclaw-gateway
systemctl --user start openclaw-gateway
```
