## Context

- Settings file: `~/.claude/settings.json`
- Plugin cache: `~/.claude/plugins/`
- Hooks directory: `~/.claude/hooks/`

## Your Task

Validate the Claude Code settings.json for integrity: dead hooks, missing plugins, conflicts, and stale config.

### Steps

1. **Read settings.json** and parse all sections:
   - `hooks` — all event types (PreToolUse, PostToolUse, SessionStart, etc.)
   - `enabledPlugins` — all plugin references
   - `permissions` — allow/deny rules
   - `env` — environment variables

2. **Validate hooks** — for each hook command:
   - Extract file path from `command` field
   - Check if the file/binary exists:
     ```bash
     test -x "<path>" && echo "OK" || echo "MISSING: <path>"
     ```
   - For `npx` commands: check if the package resolves
   - Flag: missing files, non-executable scripts, broken paths

3. **Validate plugins** — for each `enabledPlugins` entry:
   - Check if it exists in `~/.claude/plugins/installed_plugins.json`
   - If not installed but enabled → **orphan reference**
   - Run `claude plugin list 2>&1` to check for load errors

4. **Detect conflicts**:
   - Multiple hooks on same matcher (e.g., two PreToolUse:Bash hooks)
   - Duplicate plugin entries (same plugin from different marketplaces)
   - Permission rules that contradict each other (allow + deny same pattern)

5. **Present findings**:
   ```
   ═══ SETTINGS.JSON AUDIT ═══

   Hooks:
     PreToolUse:Bash  → rtk-rewrite.sh          ✅ exists, executable
     PostToolUse      → claude-flow post-edit    ⚠️  npx, not validated
     SessionStart     → memory-load.sh           ❌ file missing

   Plugins:
     claude-reflect@claude-reflect-marketplace   ✅ installed, enabled
     recall@DYAI2025-recall                      ❌ not installed, dead ref

   Conflicts: none found
   ```

6. **Ask user** what to fix, then execute approved changes

### Guardrails

- Always `cp ~/.claude/settings.json ~/.claude/settings.json.audit-backup` before any edits
- `npx` commands are hard to validate statically — flag as "not validated" rather than "broken"
- `async: true` hooks run in background and won't block — lower priority for fixing
- Some hooks use complex bash one-liners — validate the primary binary/script, not the whole pipeline
- Never remove hooks without user confirmation — they may be intentionally installed by other tools
