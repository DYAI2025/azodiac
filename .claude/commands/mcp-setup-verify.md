## Context

MCP tool installers frequently do partial setups — they register the MCP server but silently skip hooks or prompt injection when an early failure aborts the script. This skill runs the full verification and fixes anything missing.

## Your Task

Verify that a freshly installed MCP tool is fully integrated with Claude Code.

### Steps

1. **Check MCP registration**:
   ```bash
   claude mcp list 2>&1 | grep -i <tool-name>
   ```
   Expected: `<tool>: <path> - ✓ Connected`
   If missing: re-run the installer or manually add via `claude mcp add`

2. **Run the tool's own doctor/status command** (if it has one):
   - Common patterns: `<tool>-doctor`, `<tool> doctor`, `<tool> status`, `<tool> check`
   - Read ALL output — look for ✗ or warn markers

3. **Verify hooks** in `~/.claude/settings.json`:
   ```bash
   grep -A3 "PostToolUse\|Stop\|UserPromptSubmit" ~/.claude/settings.json | grep -i <tool>
   ```
   If hooks are missing, re-run the installer or manually add them.

4. **Verify prompt injection** in `~/.claude/CLAUDE.md`:
   ```bash
   grep -c "<tool-marker>" ~/.claude/CLAUDE.md
   ```
   - If 0: the installer silently skipped it (common cause: `git pull --rebase` failed early + `set -e` aborted)
   - Fix: append the tool's instruction block manually. The block is usually in the installer script — `grep -A20 "inject_prompt\|INSTRUCTIONS\|CLAUDE.md" /path/to/install.sh`

5. **Root cause if installer failed mid-way**:
   - Check if install dir has unstaged changes: `git -C <install-dir> status --short`
   - If `package-lock.json` or similar is dirty: `git -C <install-dir> checkout -- <file>` then re-run installer
   - Re-run installer BEFORE manually patching configs — let it do as much as possible first

6. **Final verification**:
   ```bash
   claude mcp list 2>&1        # Connected status
   grep "<tool-marker>" ~/.claude/CLAUDE.md  # Prompt injection present
   ```

### Guardrails

- **Prompt injection is the most commonly missed step** — always check it explicitly, even when the installer reports success
- **"Re-run install script" advice from doctor tools** can fail silently for the same reason the first run failed — fix the root cause (git lock, unstaged changes) before blindly re-running
- **Test prompt injection actually works**: in a new session, the tool should self-invoke at session start (e.g., call `buddy_status`) — if it doesn't, the injection isn't loaded yet (start a fresh session after adding)
