## Context

Test-coverage guarantees DOM string aggregates pass `noFakeDataGuard` and contain expected API values. It does NOT guarantee the page actually looks right in a browser — CSS layout, z-index, font-loading, interactive behavior all hide outside the test framework. Browser-smoke is the bridge.

Observed pattern this session: 5+ visual verification cycles. Each PR with UI impact required a browser-smoke before merge. Browser-harness already on `$PATH` per global `~/claude/browser-harness/SKILL.md`.

## Your Task

Drive Chrome via browser-harness against a running local server, inject a known profile into sessionStorage, navigate to the target hash-route, hard-clear ESM cache, take a screenshot, report what you see.

### Steps

1. **Verify server alive** on http://127.0.0.1:3000:
   ```bash
   curl -sf http://127.0.0.1:3000/health -o /dev/null -w "HTTP %{http_code}\n"
   ```
   If not 200, instruct user to start it (`npm start` with `.env` loaded).

2. **Inject profile + navigate** in a single browser-harness call. Use a known good fixture (e.g. `test/_fixtures/upstream-snapshots/profile.real.json`) so the page renders with real-shape data. Skip injection for routes that don't need a profile (e.g. `/`, `/synastry`).

3. **CDP cache disable** before reload — ESM modules cache aggressively, defeating fresh-code verification:
   ```python
   browser-harness <<'PY'
   import json, time
   cdp("Network.clearBrowserCache")
   cdp("Network.setCacheDisabled", cacheDisabled=True)
   with open('test/_fixtures/upstream-snapshots/profile.real.json') as f:
       profile = json.load(f)
   js(f"sessionStorage.setItem('azodiac_profile', {json.dumps(json.dumps(profile))}); location.hash = '#<ROUTE>'; location.reload();")
   time.sleep(3)
   wait_for_load()
   print(screenshot())
   PY
   ```

4. **Read the screenshot path** (browser-harness writes to `/tmp/shot.png`) and visually inspect via Read tool.

5. **Report findings** structured as: visible elements / missing elements / layout issues / interactive gaps. Use Critical/Important/Minor severity from `/code-reviewer` vocabulary.

### Guardrails

- **Use `new_tab(url)` for first navigation, not `goto(url)`** per global `browser-harness/SKILL.md` — goto clobbers the user's active tab.
- **Always CDP cache-disable before reload** when verifying just-merged code. ESM module cache survives `location.reload(true)`.
- **Never click sensitive UI** (auth, delete, share-card-publish) without explicit user authorization. Browser-smoke is for visual + render verification, not feature exercise.
- **Server crashes mid-smoke** → instruct user to restart, don't `pkill -9` chrome automatically.

### When to use

- After any PR that touches CSS, page-template `innerHTML`, or component DOM
- Before merging a Sprint-H-style design-shift PR
- When tests pass but the user reports "looks broken"
- As a quick "does the current main even start" sanity check

### When NOT to use

- For pure logic changes (enrichment math, tests, server.js) — tests cover those
- When server is intentionally down (the skill is local-server-coupled)
- For full e2e flows (use Playwright or similar for that)
