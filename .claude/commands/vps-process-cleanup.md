## Context

- VPS: srv1308064.hstgr.cloud (root SSH)
- User: moltbot (runs agents via systemd user services + cron)
- Common culprits: openclaw-agent (spawns 10-16 instances), whisper (3+ concurrent), zombie `du` commands
- Autostart mechanisms: systemd user services, moltbot crontab (service-guard, session-guard), systemd system services

## Your Task

Identify and kill runaway/zombie processes on the DYAI VPS, then disable their autostart to prevent respawning.

### Steps

1. **Connect and assess**:
   ```bash
   ssh -i ~/.ssh/id_ed25519 root@srv1308064.hstgr.cloud "uptime; free -h | grep Mem; ps aux --sort=-%mem | head -20"
   ```

2. **Identify bloat** — look for:
   - `openclaw-agent` × many (keep max 5, kill rest)
   - `whisper` × multiple (keep max 1)
   - `du -sm` zombie commands (kill all)
   - `nanobot` gateway (kill if requested)
   - Any process using >10% CPU for extended time

3. **Kill excess processes**:
   ```bash
   pkill -f "du -sm /home/moltbot" 2>/dev/null
   pgrep -f "openclaw-agent" | tail -n +6 | xargs kill -TERM
   pgrep -f "whisper" | tail -n +2 | xargs kill -TERM
   ```

4. **Disable autostart** if processes keep respawning:
   - Systemd user services: `systemctl --machine=moltbot@.host --user stop/disable <service>`
   - Or remove symlink: `rm /home/moltbot/.config/systemd/user/default.target.wants/<service>`
   - Crontab: `crontab -l -u moltbot | sed 's|^(.*pattern.*)|#\1|' | crontab -u moltbot -`
   - Key crons: service-guard (restarts killed services), session-guard, openclaw memory_sync

5. **Verify**:
   ```bash
   ps aux | grep -E "(openclaw|nanobot|whisper|du -sm)" | grep -v grep || echo "Clean"
   uptime; free -h | grep Mem
   ```

6. **Report** before/after load and memory

### Guardrails

- SSH connection may break when killing processes — reconnect and verify
- Always check if `service-guard.sh` cron is active — it will respawn killed services within 5 minutes
- OpenClaw gateway is a systemd USER service (moltbot), not a system service — needs `--machine=moltbot@.host --user`
- Nanobot binary can be disabled by renaming: `mv nanobot nanobot.disabled`
- Never kill: nginx, redis, tailscaled, sshd, fail2ban
- Ask user before disabling all crons — some may be intentionally running
