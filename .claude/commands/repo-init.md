## Context

User frequently creates new repos or publishes existing local projects to GitHub. The workflow should be secure by default (private repos, restrictive .gitignore).

## Arguments

- `$ARGUMENTS` — Optional: project path (defaults to current directory)

## Your Task

Initialize a project for version control with a proper CLAUDE.md, create a private GitHub repo, and push.

### Steps

1. **Assess current state:**
   - Check if git is initialized (`git rev-parse --is-inside-work-tree`)
   - Check if CLAUDE.md already exists
   - Check if .gitignore exists
   - Check if a remote is already configured

2. **Create/update CLAUDE.md:**
   - If missing, run the `/init` workflow to analyze the project and generate CLAUDE.md
   - If exists, read it and suggest improvements if needed

3. **Create/update .gitignore:**
   - If missing, create one appropriate for the project type (detect from package.json, Cargo.toml, requirements.txt, etc.)
   - Consider: should everything be ignored except specific files, or standard language-specific ignores?
   - Ask the user if unclear

4. **Initial commit:**
   - Stage CLAUDE.md and .gitignore (and other tracked files if applicable)
   - Commit with descriptive message

5. **Create GitHub repo:**
   - Use `gh repo create` with `--private` by default
   - Ask user for repo name (suggest based on directory name)
   - Set remote and push

### Guardrails

- **Always create private repos** unless user explicitly requests public
- **Check for sensitive files** (*.env, credentials, keys) before any commit
- Never auto-add files containing secrets to git
- Verify `gh auth status` before attempting repo creation
