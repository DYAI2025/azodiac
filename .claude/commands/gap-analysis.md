## Context
Generic gap analysis for any codebase: spec vs implementation, API vs UI, plan vs code, requirements vs tests. Integrates ultrathink-craftsmanship for deep reasoning and produces a writing-plans output.

## Your Task

Produce a structured gap analysis and turn findings into an actionable implementation plan.

### Step 1: Activate ultrathink-craftsmanship

Before starting analysis, invoke `superpowers:ultrathink-craftsmanship` as the reasoning compass.

Triage: this is **Tief** (deep) work — the analysis will drive future implementation decisions. Use full mode.

Frame the problem:
- **Ziel (Goal):** Understand the delta between "what should exist" and "what does exist"
- **Nicht-Ziel:** Don't fix things yet — map first, plan second
- **Constraint:** Stay in read-only analysis; no code changes during this skill
- **Erfolgskriterium:** A prioritized gap table + recommended actions + a plan file

### Step 2: Define the two surfaces to compare

Ask (or infer from context) what the two surfaces are:
- Surface A (source of truth / spec): e.g. API response, requirements doc, OpenAPI spec, PRD
- Surface B (implementation): e.g. UI pages, test coverage, feature flags, migration status

### Step 3: Map Surface A

Read, grep, or call the source-of-truth system to enumerate everything it provides.

### Step 4: Map Surface B

Read the implementation to enumerate what is actually consumed/rendered/tested.

### Step 5: Produce gap table

```
| ID  | Surface A (spec)     | Surface B (impl)     | Status   | Severity |
|-----|----------------------|----------------------|----------|----------|
| G01 | field X              | not rendered         | MISSING  | HIGH     |
| G02 | endpoint /foo        | wired via proxy      | OK       | —        |
| G03 | field Y              | shows "—" fallback   | PARTIAL  | MEDIUM   |
```

Severity:
- **HIGH** — user-visible failure or data loss
- **MEDIUM** — degraded UX, workaround exists
- **LOW** — cosmetic or edge case

### Step 6: Apply ultrathink Phase 3 (Craftsmanship check)

Run each gap through:
- **Simplicity:** Is the fix actually simple and I'm overcounting it as a gap?
- **Testability:** Does a test already cover this, making it a false gap?
- **Reversibility:** Can I fix this without breaking other surfaces?

### Step 7: Invoke writing-plans

After the gap table is confirmed, invoke `superpowers:writing-plans` with:
- Goal: "Fix all HIGH + MEDIUM gaps found in gap analysis [date]"
- Pass the gap table as context
- The plan should have one task per gap (or group closely related gaps)

### Guardrails
- Stay read-only during analysis — no code edits
- Mark assumptions explicitly (`ASSUMPTION:`)
- Distinguish "gap I can see in code" vs "gap that needs live test to confirm"
- Don't propose solutions during analysis — that's writing-plans' job
