## Context
You are auditing what services are running on a remote system (Linux server, VPS, etc.) accessed via SSH. This helps quickly understand the system state and locate specific services.

## Your Task

Discover running services, identify listening ports, locate service directories, and provide access information for services on a remote system.

### Steps

1. **Ask for Target Services**
   What services is the user looking for?
   - Specific service names (e.g., "nginx", "postgresql", "evermemos")
   - Service categories (e.g., "web servers", "databases")
   - Or "all" for complete system audit

2. **Find Running Processes**
   ```bash
   ssh USER@HOST "ps aux | grep -E '(SERVICE1|SERVICE2|SERVICE3)' | grep -v grep"
   ```

   For broader search:
   ```bash
   ssh USER@HOST "ps aux | grep -E '(python|node|java|nginx|apache|docker)' | grep -v grep"
   ```

3. **Identify Listening Ports**
   ```bash
   ssh USER@HOST "netstat -tulpn 2>/dev/null | grep LISTEN || ss -tulpn 2>/dev/null | grep LISTEN"
   ```

   Common ports to note:
   - 80/443: HTTP/HTTPS
   - 3000: Node.js/Next.js dev servers
   - 5000: Flask/Python services
   - 8000/8080: Alternative HTTP
   - 27017: MongoDB
   - 5432: PostgreSQL
   - 6379: Redis

4. **Locate Service Directories**
   ```bash
   ssh USER@HOST "find ~ -maxdepth 3 -type d -iname '*SERVICE_NAME*' 2>/dev/null"
   ```

   Common locations:
   - `~/service-name/`
   - `~/.service-name/`
   - `/opt/service-name/`
   - `/var/www/service-name/`

5. **Check Service Configuration**
   ```bash
   # Find config files
   ssh USER@HOST "find ~/SERVICE_DIR -name '*.conf' -o -name '*.config' -o -name '.env' -o -name 'config.json' 2>/dev/null"

   # Read important configs
   ssh USER@HOST "cat ~/SERVICE_DIR/config.json" 2>/dev/null
   ```

6. **Check Service Health**
   ```bash
   # Check logs
   ssh USER@HOST "tail -20 ~/SERVICE_DIR/logs/*.log 2>/dev/null"

   # For systemd services
   ssh USER@HOST "systemctl --user status SERVICE_NAME"

   # Check if web service responds
   ssh USER@HOST "curl -s http://localhost:PORT/health || curl -s http://localhost:PORT/"
   ```

7. **Provide Access Summary**

   Create a summary showing:
   - **Service Name**
   - **Status:** Running / Stopped
   - **PID:** Process ID
   - **Port(s):** Listening ports
   - **Directory:** Installation path
   - **Access URL:** How to reach it
     - Local: `ssh -L PORT:localhost:PORT USER@HOST` then `http://localhost:PORT`
     - Tailscale: `http://TAILSCALE_IP:PORT`
     - Public: `http://HOST:PORT` (if exposed)

### Discovery Patterns

**Web Services:**
```bash
ssh USER@HOST "ps aux | grep -E '(next|nginx|apache|node.*server|python.*app)' | grep -v grep"
ssh USER@HOST "netstat -tulpn | grep -E ':(80|443|3000|8000|8080)'"
```

**Databases:**
```bash
ssh USER@HOST "ps aux | grep -E '(mongod|postgres|mysql|redis)' | grep -v grep"
ssh USER@HOST "netstat -tulpn | grep -E ':(27017|5432|3306|6379)'"
```

**AI/ML Services:**
```bash
ssh USER@HOST "ps aux | grep -E '(python.*server|jupyter|streamlit|gradio|ollama)' | grep -v grep"
```

**Docker Containers:**
```bash
ssh USER@HOST "docker ps"
ssh USER@HOST "docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'"
```

### Guardrails
- **Use grep -v grep** to exclude the grep command itself from results
- **Check both netstat and ss** (ss is newer, but not always available)
- **Search home directory first** (`~`) before system directories
- **Limit find depth** to avoid scanning entire filesystem (use -maxdepth)
- **Handle permission errors** gracefully (use `2>/dev/null`)
