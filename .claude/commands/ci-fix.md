## Context
The user pastes CI failure output (GitHub Actions, Railway, etc.) and wants it fixed and shipped in one flow.

## Your Task

Diagnose the CI failure, implement the fix, verify locally, then commit and push.

### Steps

1. **Parse the CI output** — identify the exact error type:
   - Lint failure (ruff, flake8) → identify files and rule codes
   - Type check failure (mypy) → identify files and error messages
   - Test failure (pytest) → identify failing tests and tracebacks
   - Import error → identify missing module and trace the import chain
   - Build failure → identify the build step that failed

2. **Determine if CI runs on a different branch than local** — check:
   ```bash
   git branch --show-current
   git log --oneline main -3
   git log --oneline HEAD -3
   ```
   If the fix already exists locally but CI runs on `main`, the fix needs merging, not re-implementing.

3. **Fix the root cause locally**:
   - For lint: prefer `ruff check --fix` over manual edits
   - For imports: trace the full import chain, fix at source
   - For tests: read the failing test, understand what changed, fix code (not test) unless test is wrong

4. **Verify locally** — run the same CI commands:
   ```bash
   ruff check <path>/ --output-format=github
   mypy <path> --ignore-missing-imports
   pytest -v --tb=short
   ```

5. **Ship** — stage only relevant files, commit with `fix(ci):` prefix, push.

### Guardrails
- Never fix lint by adding `# noqa` — fix the actual issue
- If the CI error is on `main` but already fixed on current branch, suggest merging instead of re-fixing
- Check if the error is a symptom of a deeper problem (e.g., wrong module name used everywhere)
- Run the exact CI command locally before committing to avoid a fix-fix-fix cycle
