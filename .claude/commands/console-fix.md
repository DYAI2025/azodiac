## Context
User pastes browser console output. Goal: identify the ONE root cause behind multiple error lines, fix it properly — not patch symptoms.

## Your Task

Fix the reported browser console errors.

### Steps

1. **Read ALL error lines before touching any code**
   - Group related errors (one root cause often generates 3-5 downstream errors)
   - Identify the FIRST error in the chain — that's usually the root cause
   - Common misleading patterns:
     - `postMessage failed` / `frame-src CSP violation` → often caused by a blocked third-party script, not a CSP misconfiguration
     - `Failed to execute 'observe' on 'IntersectionObserver'` → usually caused by a component that failed to mount (check the error above it)
     - Multiple `undefined` errors → usually one missing import or failed API call upstream

2. **Classify the error type**
   - **Blocked API/Script** (ApiTargetBlockedMapError, 403, CORS) → replace the dependency, not the config
   - **CSP violation** → add origin to `server.mjs` helmet CSP directives
   - **Deprecated API** → check MDN/docs for replacement, implement replacement
   - **Runtime crash** → find the component, read it, fix the null check

3. **Fix root cause, not symptoms**
   - If an API key is blocked → replace the whole integration (e.g., Google Maps → Nominatim)
   - If CSP blocks a new domain → add it to `connectSrc`/`scriptSrc`/`imgSrc` in `server.mjs`
   - Do NOT add `unsafe-inline` or `*` to silence CSP errors

4. **Verify fix**
   ```bash
   npm run build 2>&1 | tail -10
   npx tsc --noEmit 2>&1 | grep -v "features/plan"
   ```
   Open browser, confirm errors are gone.

5. **Ship**

### Guardrails
- Read the full component before editing — don't patch blindly
- CSP changes always go in `server.mjs` helmet config — never in `index.html` meta tags
- If replacing a third-party SDK: check all files that import from it (`grep -rn "import.*from"`)
- After Google Maps removal: also clean up `scriptSrc` in CSP — don't leave dead entries
